## Goal：只解决哪一个问题

让用户在第一次回答中知道「最值得理解的是什么、为什么这样解释、具体是什么意思」，
追问时能沿着同一问题深入，而不是收到术语堆积、泛泛画像、反复免责声明或空泛建议。

这次学习指从人工收集的 Chat 回答中提炼写作方法，并改进现有 Skill 指令与少量示例。
不训练模型权重，不接模型 API，不建立检索库，不把聊天原文整批塞进上下文。

成功不是回答更长、更短、更像某家模型或更让人「觉得准」，而是：

1. 开头回应当前问题，不先重排全盘或重述全部出生信息。
2. 有依据的含义得到实质解释，而不只剩「仅供参考、不能判断」。
3. 术语、解释及其适用条件在需要它们的地方连在一起。
4. 每段提供新信息，同对象追问不重启整篇报告。
5. 示例更具体但没有增加新的命理结论、人物经历、职业适配或预测。

## 写法裁决：学什么、怎样落地

### 4. 四份样本只提炼这四类方法

| 样本   | 采纳的方法                                                 | 明确丢弃                                                       |
| ------ | ---------------------------------------------------------- | -------------------------------------------------------------- |
| Claude | 回答在前、依据随后；围绕追问展开；纠正时定位具体前述判断   | 从命盘推荐岗位或月份；把简短当作所有问题的统一长度             |
| GPT    | 区分易混概念；说明差别带来的实际含义；给出可观察的辨别方式 | 开头、分节、小结重复同一结论；为虚构输入自动改成小说人物塑造   |
| 豆包   | 自然口语、简短对话、一个贴切比喻或小场景                   | 「其实你心里」「他不是故意的」等读心；戏谑或贬义人格标签       |
| Gemini | 尽快进入具体情境，用对照解释抽象概念                       | 「面具」「冷暴力专家」等定性；无依据百分比；把失败改称其他应验 |

这不是按品牌混合语料，也不是生成时必须模仿四种风格。最终指令不要求宿主扮演或提及
这些模型；写法原则应脱离模型名称独立成立。样本中的全篇粗体、表格与栏目格式不搬入正文。

### 5. 首次回答

- 第一段进入当前问题最有价值的一点；不固定使用「你是一个……的人」作人格总判。
- 从计划里选择足够回答问题的一小组材料；不按四体系各写一段，不把所有事实逐条翻译。
- 在必要处给出传统术语，并紧邻解释它在当前问题中表示什么。只是翻译术语名称不算解释。
- 规则含义允许的具体化才可以写；结构值本身不授权推导性格、职业或关系。
- 回答够用就停。不得规定统一字数、段落数、固定三个特点或固定建议条数。
- 只有一个受支持的重点，就讲清这一点；如果没有可解释含义，诚实说明缺口，不靠写作补齐。

上述是选材和组织方法，不是用户可见的「结论—依据—场景—限制」四段模板。
正文仍是自然段；用户明确索要技术信息时才单独展开对应依据。

### 6. 具体化的合法方式

优先使用一个能说明差别的对照，或一个与获准含义等价的小场景。对照、比喻不能带入新性格、
动机、能力、因果或事件。例如获准材料仅支持一个结构分类，就不能用职场故事替它补成人格结论。

- 场景明确是说明，不是认定经历；没有用户自述时用「例如」「如果处在……」等自然条件。
- 假设场景也须在原结论含义内；加「可能」不能使无依据判断合法。
- 比喻帮助解释一个点即可，不连续写内心独白，不替用户或伴侣认定真实动机。
- 真正有用的辨析要说明区别在哪里，不写「理性又感性、稳重又冲动」式双面包容画像。
- 用日常语言，但不通过羞辱、诊断标签、恐吓、奉承或强烈确定感制造「很准」的体验。

### 7. 同对象追问与纠正

追问只展开被问到的那个判断：解释原机制、给一个合适的区分或例子，必要时补上会改变它的条件。
不重复全盘、已解释术语和所有限制；不把原材料不足伪装成还有更深结论待付费或待补无用资料。

用户说「不符合」时，区分两种情况：

1. 先前确实说错、说过头或遗漏条件：指出具体一句并撤回或收窄，再据当前材料重写。
2. 只是不知道用户现实是否符合：承认传统解释不能替代现实观察，不编造对方隐藏动机。

不默认同意所有质疑，也不维护每个判断必然成立。不用「应在别处、应期延后、你已经化解」
兜底挽救预测；若没有对应预测材料，直接撤回该预测。用户修订对象、时间或设置时按现有链路
重新取计划和绑定，不复用旧草稿；本轮不新增会话状态机制。

### 8. 信息不足、能力不足与限制

- 以实际 `answerPlan.answerability`、选中事实及相关 warning 为准，不自己重新判定能力。
- 未知时间不能靠午时占位生成确定性画像，也不能退回「三柱已经确定大部分性格」的说法。
- 有整日稳定且已准入材料时只讲它；没有时不承诺「以下仍可解读稳定部分」。
- 用户已说无法补时间，不继续索取；只有现有计划认定补某项能推进当前请求时才问那一项。
- 不把未实现、内部失败或来源未准入统称为「资料不足」。
- 约估/近边界的影响只在相关判断旁说明，不为美化语言删掉必要限制，也不增加无关尾段。
- 时运不可答时不拿本命背景顶替，不给具体月份，不用一段通用职场建议假装回答应期。

本轮若替换 `reading-style.md` 现有 warning 示例，必须使其忠实于这些已实现行为，
只改转写文字，不改产生或消费 warning 的代码。

### 9. 事业与现实建议

继续遵守 ADR 0021：最多一条计划实际提供的十神文化参考，短释和非职业预言边界紧邻；
不由此推出职业、行业、人格或工作环境匹配。只有出生信息，不给行动建议。

有用户自述时，实际做法只来自自述的角色、困难、目标等；与命盘段落分别保留来源。
不把有用的通用建议改写成「你的命盘说明你应该这样做」，不展示审计口吻的来源声明。
本轮不为追求好看而改变职业层权限。

## 实施处方：如何改现有文件

### 10. `reading-style.md` 的改法

先通读，然后就地整合，不在文件末尾机械追加整套新规范。

1. 保留简洁的目标、证据边界、事业/关系特殊约束、材料限制和实际交付要求。
2. 把重复的「不得」「不要」合并；保留能解释原因的必要反例，不扩关键词黑名单。
3. 将首次回答、追问和纠正的正面做法写进相应段落，避免形成第二套独立风格系统。
4. 放入至多三个原创的正面示范片段：重点解释、具体辨析或场景、同对象追问。
   三者是写作技能，不强求来自三个体系，也不强求对应三个完整命盘。
5. 现有拒答示范可以精简保留，但不能继续成为示例的全部内容。
6. 文件总体以不增长为目标；必要新增应替换重复要求。报告删减与新增的用途，不以字节变小
   证明质量，也不能为了净减少而删掉证据或交付义务。

每个正面片段要把「示范前提」和「用户正文」分开：前者给宿主看，后者才是可表达的文字。
不把前提标签、规则路径、来源编号、内部解释过程或验证输出漏进正文。

### 11. 正面示例的事实来源

执行者先用仓库内已确认合成输入和当前 bundle 取得真实 `answer-plan`，只从当前请求实际选中、
允许且带有相应含义的材料原创写作。优先选现有 Western/Zi Wei 等规则中确有解释含义的片段；
这只是选材顺序，不能把整个体系或所有规则族视为自动准入。不得为凑八字特色开放格局等材料。

逐个记录：当前输入身份、topic/lens、实际 fact/机制路径、规则版本、能支持的含义及必要限制。
完整计划、命令和验证结果放本地临时证据中；示例前提仅保留足够防止错误套用的简要信息。
不把偶然 fact 编号当永久身份，不照抄教师模型的星位或结论，不把自己构造的规则输出冒充实跑。

正文可少选相关材料，不能篡改完整送检计划。每个示例都用其真实当前上下文走既有绑定交付和
措辞检查；失败则修正文案，不能改检查器。检查全绿仍不证明语义忠实，Codex 逐句对照来源。

如果某个期待中的例子只有结构值、没有获准含义，换用已有可用材料；确实找不到时报告具体缺口，
不另立来源研究或开放权限来凑示例。材料缺口只阻断依赖它的例子，不拖延其他合法改进。

### 12. `SKILL.md` 的改法

优先不改。只有主入口未能加载规范，或旧表达指令与精简后的规范真实矛盾时，才做最小修改。
不把参考文件内容复制进主入口；不新增每次必读四份样本或另一份长风格文件的要求。

保持普通问题的既有链路：当前 `answer-plan` → 当前草稿 → 密封 → 带当前上下文绑定验证 →
仅展示返回的成功 `deliverableBody`。改文字后重新密封与送检，不能在成功文本后再润色。
沿用现有 lint 要求与技术详情请求方式；`bazi-career` 的结构输出不变成默认自然语言回答入口。
