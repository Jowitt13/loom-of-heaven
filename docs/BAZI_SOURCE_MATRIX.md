# BaZi Reasoning 2.0 source matrix

> Status: Proposed source registry for ADR 0015. It authorizes no Reasoning 2.0 code by itself.
> A row must pass its stated gate before an implementation task may treat it as adopted.
>
> Last reviewed: 2026-08-14. Repository and license metadata for external GitHub references were
> checked on that date; source code, embedded books, tables, and every transitive license still
> require a fresh review before reuse.

## Purpose

This matrix keeps four questions separate:

1. What does a classical or school source claim?
2. How does Loom operationalize that claim as deterministic software?
3. Which disagreements or boundary cases remain?
4. Do rights permit the exact text, table, translation, or code to be stored and shipped?

A rule is not source-cleared merely because another open-source project implements it. External
projects are coverage references and bug-finding aids, never metaphysical ground truth.

## Status vocabulary

| Status                | Meaning                                                                                               |
| --------------------- | ----------------------------------------------------------------------------------------------------- |
| `FROZEN_LEGACY`       | Existing `bazi-rules-ziping@0.1.0` behavior only; not approval for enhanced semantics                 |
| `ACCEPTED_STRUCTURAL` | Stable structural definition accepted for an implementation slice after its table/fixture gate passes |
| `CANDIDATE_RULE`      | Worth specifying, but the exact operational rule has not passed source and case review                |
| `BLOCKED_EDITION`     | Classical work is identified, but exact edition/chapter/text or table provenance is not frozen        |
| `BLOCKED_SCHOOL`      | The concept differs materially by school and no profile has been selected                             |
| `REFERENCE_ONLY`      | May inform coverage or tests; cannot supply runtime code, text, or truth                              |
| `EXCLUDED`            | Must not be used in the proposed runtime or shipped source corpus                                     |

## Source registry requirements

Before a new rule id is implemented, its machine-readable or reviewable registry entry must include:

```text
sourceId
work and attributed author/tradition
edition or scan identity
chapter/section/page or stable locator
source-language claim (short quotation only when lawful and necessary)
project-authored paraphrase
Loom operationalization
rule type: structural | interpretive | school-specific | heuristic | supplemental
disputed: true | false
rights status for original, edition, transcription, and translation
reviewer and verification date
adversarial case ids
```

The original public-domain work and a modern edited edition are different copyright objects. A
public-domain title does not grant permission to copy a modern commentary, typeset edition,
translation, database, or another repository's transcription.

## Copyright and data boundary

- Do not commit full modern books, commentaries, translations, commercial tables, screenshots, or
  another repository's reference corpus.
- Store only project-authored operational rules, minimal lawful source quotations where necessary,
  public-domain source locators, and independently created synthetic fixtures.
- A software MIT license does not automatically license embedded book text or translated rule
  tables. Audit code license, content rights, translation rights, and data provenance separately.
- Real birth histories and hindsight events are prohibited from git fixtures. Research-mode
  preregistration/validation data, if ever added, requires a separate privacy and consent design.
- Classical-source agreement does not establish scientific predictive validity. User-facing output
  remains traditional-culture and self-reflection material.

## Implementation admission checklist

A Codex commander task may mark a source row in scope only when all answers are yes:

1. Is the exact source claim and edition/locator recorded?
2. Is the Loom operationalization written independently and testably?
3. Are school assumptions and disputed alternatives explicit?
4. Are original, edition, transcription, translation, and code rights acceptable?
5. Are the relevant adversarial case ids named?
6. Can the result return rejected or unresolved where the evidence conflicts?
7. Does the change preserve the frozen 0.1 ruleset?
8. Does the output avoid probability, medical meaning, and deterministic life-event claims?

If any answer is no, the executor must stop that rule rather than fill the gap from model memory.
