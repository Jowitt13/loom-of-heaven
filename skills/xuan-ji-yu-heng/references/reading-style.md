# 自然叙述规范 v1

本文件约束默认交付给用户的专题解读。先回答用户真正问的事，再解释必要的依据和限制；事实与规则留在内部可追溯，不把回答写成术语课或后台审计单。

## 交付面只有正文

默认回答只输出连贯的自然段落。不要自动附加标题、步骤编号、来源区、告警区、声明区、技术附录或“还想看什么”的菜单，也不要使用“讲人话”“专业依据”“结论如下”“声明”“风险提示”“引擎警告”等栏目化语言。

`interpretation.json` 中的 `facts`、`evidence`、`reason`、`caveat`、`warnings`、`disclaimers`、`followupOffers` 都是写作和审计输入，不是默认展示字段。它们只在用户明确要求查看盘面、计算详情或推理来源时按需展开。

## 每个判断的内部推理链

先在内部完成下列链路，再写成自然语言：

```text
盘面事实（claim / evidence）
  → 规则机制（reason / 版本化 ruleset）
  → 当前问题中的现实倾向、场景或建议
  → 适用条件、输入精度或流派限制（caveat / warnings）
```

不得跳过前两项直接写结论，也不得把一个没有对应 `evidence.ref` 或 `ruleId` 的新盘面事实写入正文。

仅有星位、宫位或十神位置，不等于已经有了职业、人格、配偶或收入含义。相关规则没有提供这种含义时，不补写；用户问技术细节才解释结构记录。缺少 `reason` 字段本身也不等于事实无效，关键是所写含义是否有独立可解析的已准入规则支持。加上“倾向”“参考”不能替代缺失的依据。

## 首次回答：从最值得理解的一点开始

第一段直接进入当前问题最有价值的一点，不用“你是一个……的人”式的总判开头，也不先重排全盘或复述出生信息。从当前计划里选足够回答问题的一小组材料；四体系是能力范围，不是四段等长答案，也不把所有事实逐条翻译成正文。术语确有解释价值时才出现，并紧跟它在当前问题中意味着什么——只翻译名词不算解释。

回答够用就停，不规定统一字数、段落数或固定特点条数；当前材料只支持一件事，就把这一件事讲清楚。没有可解释含义时诚实说明缺口，不靠写作补齐。表达方式按事实选择：因果仅在返回规则明确支持该因果链时使用，位置并列不是因果；只有返回了对应时段的事实才谈趋势，没有应期依据就说明不能判断；多体系分别保留各自的依据与限制，没有综合记录不写“共同表明”“相互印证”。

### 示范片段：解释一个有依据的重点

示范前提（给宿主看，不进入正文）：仓库合成输入，`--topic character`；材料为当前 answerPlan 选中的已准入事实——紫微命宫主星武曲、破军及各自星性，武曲化权坐命宫，双星亮度「平」，五行俱全；规则版本 `ziwei-rules@0.1.0`、`bazi-standard@0.1.1`。正文经当前 CLI 密封并绑定送检通过，完整计划、命令与验证结果存本地证据。以下才是可表达的文字：

> 这张盘最值得先说的是紫微命宫里武曲与破军同宫：命宫主星在紫微体系里被看作核心性格的底色，武曲的星性是刚毅果决、善于理财与执行，破军的星性是变动性强、敢于破旧立新。同宫的读法是两种侧重并存——一件事要拍板推进，武曲一侧给的是果决和执行力；局面要打破重来，破军一侧给的是敢动的底子。星性只说明这两种侧重同时在这份底色里，并没有说人更追求变化还是更守着安稳，那是处境和选择的事；这些读法本身也是传统体系的结构分类，用来看倾向可以，不是确定性预测。
>
> 武曲还带「化权」：四化里的化权，传统上指掌控力与主动性的增强，它落在命宫、也就是作用在性格底色上，常读作竞争意愿和主动性偏高。两颗主星亮度都是「平」，即能量中性、无明显增减，这些特点按平常力度理解就好，不必往极强或极弱里读；这份读数按排盘返回值转述——真太阳时采用近似方法，位置贴着分界时，这类分类可能随校正移动。
>
> 结构上还有一点顺带说明：这张盘五行俱全。传统命理里，五行齐全或缺失本身并不直接定吉凶——缺某一行不等于凶，轻重要结合整体喜忌来看。

它示范的写法：开头即最有价值的一点；术语（命宫主星、化权、亮度）出现时紧邻机制与含义；场景只到星性支持的“两种侧重并存”，不再扩写成选择偏好或行为习惯，并明说星性没有回答偏好哪一侧；必要限制写在它限定的判断旁边——非预测贴着读法、近似与分界贴着读数、五行轻重贴着五行——不另起免责尾段。示例只演示方法，实际选材依当前计划。

## 具体化与辨析

可以用一个对照、比喻或小场景帮助理解，但它必须在已获准含义之内：场景是说明，不是认定经历；没有用户自述时用“例如”“如果”“常见表现可能是”等条件表达，加“可能”不能使无依据判断合法。对照和场景只展开到获准含义的粒度——规则给了“执行”与“变动”两种侧重，就讲这两种侧重，不落到“没有改进需要时仍想变”“不喜欢长期稳定”这类原材料没有的选择偏好或行为习惯。不编造用户或伴侣的经历与隐藏动机，不用贬义标签、奉承或恐吓制造“很准”的感觉，不写“理性又感性、稳重又冲动”这类正反全包、无法区分的画像。有用的辨析要说明差别在哪里、各自在什么场景显现，先确认事实确有可比较的依据。

### 示范片段：用辨析分清两个侧面

示范前提：同一合成输入，`--topic wealth`；材料为财帛宫主星组合（廉贞、七杀）的获准含义与机制（财帛宫主星决定理财风格与进财方式），规则版本 `ziwei-rules@0.1.0`；同样经密封与绑定送检通过。用户问“这是不是说我存不下钱”。以下为用户正文：

> 「赚钱能力强但花销也大」是两个不同侧面的描述，分开看更清楚：财帛宫主星描述进财方式与理财风格（这是传统体系的结构分类，不预测你的实际财务），廉贞加七杀的组合，指进财来源多元、赚钱能力强；而「花销也大」说的是开支一侧的倾向。合起来它并没有说「存不下钱」——结余多少取决于收支两边怎么平衡，传统分类对此没有结论，你的实际收支也不是盘面能替你回答的。这份宫位判读按返回读数转述；真太阳时按近似方法计算，读数若贴着分界，可能随校正移动。

它示范的写法：把一句复合结论拆成两个侧面，说明各自指什么；诚实指出规则没有覆盖的部分（结余），不用盘面冒充现实答案；限制不另起尾段，“传统分类非预测”随宫位判断句就地说出，近似与贴界随读数转述一并交代。

## 同对象追问与纠正

追问只展开被问到的那一点：补机制、给一个区分或例子、必要时补会改变判断的条件。不重复整份回答，不重新定义已解释过的术语，不重讲全部限制，也不把材料不足伪装成还有更深结论待补。用户修订对象、时间或设置时，按现有链路重新取计划、重新密封送检，不复用旧草稿。

用户说“不符合”时分两种情况处理：先前确实说错、说过头或漏了条件——指出具体哪一句，撤回或收窄，再据当前材料重写；现实情况未知——承认传统解释不能替代现实观察，不编造隐藏动机。不默认所有质疑都正确，也不维护每个判断必然成立；没有对应预测材料时直接撤回预测，禁止用“应在别处、应期延后、你已经化解”挽救。

### 示范片段：围绕同一点回答追问

示范前提：同上 wealth 计划；首次回答已解释过财帛宫与廉贞、七杀的含义，用户接着问“赚钱能力强具体是什么意思，能举个例子吗”。经密封与绑定送检通过。以下为用户正文：

> 单说「赚钱能力强」这一句：它指进财一侧的能力——还是财帛宫主星这条线索，廉贞加七杀的组合，传统上读作进财来源多元、赚钱这一侧能力强（这是传统结构分类，不是对你收入情况的预测）。「来源多元」说的是进财形态不只一种：可能体现在主业里不同构成的进项，也可能体现为工资之外的某种进账形态；具体哪一种会出现在你身上，盘面没有说，而结余要等开支一侧合起来看。这份宫位判读按返回读数转述；真太阳时为近似计算，读数若贴着分界，可能随校正移动。

它示范的写法：只解释被问的那一句，用“还是……这条线索”衔接而不重新上课；「来源多元」只作概念说明（进财形态不止一种），不认定用户有副业、愿意接单或会同时推进几条线；限制随判断句就地一句，不重讲全盘。

## 信息不足与不可答

以当前 `answerPlan.answerability`、选中事实和相关 warning 为准，不自行重新判定能力。未知时间没有获准的稳定材料时，不承诺“三柱已能确定大部分性格”，也不用午时占位生成画像；用户已说无法补时间，不再反复索取。未实现、内部失败、来源未准入和资料不足是不同原因，如实区分，不统称“资料不足”。时运不可答时直接说明，不拿本命背景或通用职场建议顶替应期答案，也不给具体月份。

## 术语要自然落地

专业名词不是每段的必选项。确有必要时再用，并在同一句或紧接着的句子里解释；已解释过的词不反复定义，不为显得专业而增加术语。

不要写：

> 七杀说明你适合竞争激烈的岗位。

可以写：

> 命盘里有「七杀」，传统上用它谈权威、压力、竞争。这只是事业与责任主题的文化参考，不是职业预言，也不能据此判断你适合什么工作。

这个例子只适用于 answerPlan 已提供该十神及其短释的情况，不是通用开场白。事业现实做法另据用户自述，不能从这条文化参考推出。只有位置记录、没有含义规则时的写法见 `examples-love.md` 的单人盘示例。

## 事业正文（ADR 0021）

事业默认正文在一般叙述规则上再收窄：用户自述现实优先；命盘至多一条十神文化参考（名 + 紧邻短释 + 非职业预言）；不得写入格局、喜用、五行行业或由命盘推出的职业/行业方向。详见 `examples-career.md`。

## 告警和边界的自然转写

只有当限制会改变当前问题的判断时才提及它。不要展示 warning 名称、错误代码、provider、规则版本、事实编号或来源路径。

| 内部情况               | 默认写法                                                                                         |
| ---------------------- | ------------------------------------------------------------------------------------------------ |
| 出生时间未知或误差较大 | 出生时间若前后相差较大，上升、宫位或时柱相关的判断可能会变化；以下更侧重对这一误差不敏感的结构。 |
| 某体系无法计算         | 当前资料不足以支持这一层面的判断，因此不作延伸推断。                                             |
| 靠近分类边界           | 这个位置靠近分界，时间稍有调整时分类可能不同，不把它当成唯一依据。                               |
| 流派分歧               | 这里不同流派采用的口径并不完全一致，因此只保留它们共同支持的部分。                               |

不受当前问题影响的内部 warning 不显示。禁止固定免责声明页脚；传统文化、非科学预测和重大决定的边界由产品入口说明。涉及健康、法律、投资、生命安全或重大关系决定时，只在对应段落中给出最小必要的自然提示。验证器要求的 caveat 与 warning 也照此转写：各挂在它所限定的判断旁边，一句说清，不堆成尾段。

## 关系与合盘

单人盘不代表两人的相互吸引、对方的想法或现有关系。只有单人结构记录时，不把它改写成合盘结论，也不把“夫妻宫”直接写成真实配偶的体貌或性格。相处模式或建议仍须有对应规则、配对结果或现实信息；不得写“注定在一起”“必分手”“必然结婚”“命定伴侣”，也不得用同义表达替代。若需要说明边界，融入相关段落，例如：

> 这些结构更适合帮助你们识别靠近与卡住的方式；关系是否走得长远，仍取决于沟通、边界和双方当下的选择。

## 内部来源记录（默认不展示）

每个段落都应保留追踪信息，供测试、审计和用户主动追问时使用：段落标识、事实引用（`InterpretationFact.evidence[].ref`）、规则引用（如 `bazi-rule/...` 等版本化规则）、当前结果中的 ruleset id 与版本、reason 的受控摘要、相关 caveat 与 warning、以及本段允许写的结论。以上字段说明在本页自足可用；完整类型定义位于仓库开发文档 `docs/NARRATIVE_OUTPUT_V1.md` 的 `NarrativeTrace`，仅供开发者参考，不是安装后运行的必读依赖。

来源优先级固定为：计算出的 `ChartBundle` 事实 → 版本化 ruleset → ADR / 来源矩阵 → provider/provenance。宿主模型只能组织这些材料，不能新增盘面事实、规则或事件承诺。

## 交付前检查

普通问题一律走绑定交付链路（当前 `answer-plan` → `reading-draft/v2` 草稿 → 密封 → 带当前上下文绑定送检 → 仅展示返回的 `deliverableBody`），流程与命令见 `SKILL.md` 与 `answer-contract.md`。本文各示范片段的正文即按该链路产生并通过检查的原文；改一个字都要重新密封送检，不得沿用旧正文。

对草稿文本另按需运行措辞检查：

```bash
node scripts/loom-chart.mjs lint-reading --input-file draft.md --channel topic
```

`ok: true` 才可交付。它会阻止后台标签、原始来源标识、固定页脚、自动追问、空话、重复和越界断言；绑定送检已内置这一步。检查通过不等于语义正确，输出仍须与内部追踪信息对照。

用户明确要求“依据是什么”“看原始盘面”“计算设置是什么”时，单独提供技术详情，而不是把技术字段混进默认正文。
