# 自然叙述规范 v1

本文件约束默认交付给用户的专题解读。先回答用户真正问的事，再解释必要的依据和限制；事实与规则留在内部可追溯，不把回答写成术语课或后台审计单。

## 交付面：便于扫读的正文

默认回答是便于扫读的自然叙述：先给与当前问题有关的重点；内容较多时用短标题分组（标题概括本组内容，不套性格/事业/感情/财运固定栏目）；并列信息用简短列表，一个要点一件事；重点词或短句适量加粗，正文保留普通字重，不全篇加粗；段落与列表之间留白。短追问可以只有一两段，不强制标题、固定特点条数或四体系份额。排版服务于内容，不为凑整齐增加内容；字型字号由宿主控制，Skill 只写文本结构（`reading-draft/v3` 的短标题、成对加粗与要点行）。

不要自动附加来源区、告警区、声明区、技术附录或“还想看什么”的菜单，也不要使用“讲人话”“专业依据”“结论如下”“声明”“风险提示”“引擎警告”等栏目化语言。标题不得承载正文没有依据的新结论。

`interpretation.json` 中的 `facts`、`evidence`、`reason`、`caveat`、`warnings`、`disclaimers`、`followupOffers` 都是写作和审计输入，不是默认展示字段。它们只在用户明确要求查看盘面、计算详情或推理来源时按需展开。

## 每个判断的内部推理链

先在内部完成下列链路，再写成自然语言：

```text
盘面事实（claim / evidence，引擎计算）
  → 规则机制（reason / 版本化 ruleset，已实现规则含义）
  → 宿主传统解释（基于上两层展开的分析；roadmap v3.4 起允许）
  → 当前问题中的现实倾向、场景或建议
  → 适用条件、输入精度或流派限制（caveat / warnings）
```

不得跳过盘面事实直接写结论，也不得把一个没有对应 `evidence.ref` 或 `ruleId` 的新盘面事实写入正文：已实现规则给出含义时如实使用；没有预写释义时，用你自己的传统解释（第三层）紧贴该事实讲清机制与本题含义，不因“缺词典条目”留白。

**来源三层与解释职责（roadmap v3.4）：**引擎计算的事实与已实现规则的含义可以按引擎结果陈述；
你自己的传统解释必须紧扣所引用的事实，但**不得**说成引擎规则结论，规则版本不替整段解释背书。
缺少预写释义不再等于不能回答——可以用传统知识解释真实盘面（例如官禄宫星性如何指向一类工作
方式），但仍不得编造未计算的位置、数值、时期或关系事实。正文不打印层标签；用户追问依据时再
分层展开。职业领域只能作为传统象义的探索方向，不包装成现实职业适配鉴定。

## 首次回答：从最值得理解的一点开始

第一段直接进入当前问题最有价值的一点，不用“你是一个……的人”式的总判开头，也不先重排全盘或复述出生信息。从相关材料里抓**少数主线**：讲清最值得理解的一点，需要时补一个相关侧面即可；四体系是能力范围，不是四段等长答案，更不把全部选中事实逐项翻译成“材料巡览”。用户明确要求全面展开时可以增深，但不能把每个体系都填满当完成标准。术语确有解释价值时才出现，并紧跟它在当前问题中意味着什么——只翻译名词不算解释。

结构位置（如某宫某星、某柱某十神）是可以解释的真实材料：没有预写释义时，用你自己的传统知识解释它（来源第三层），讲清机制与本题含义，不冒充规则结论；与本题无关的位置不塞进正文充数。解释有主次、有取舍：强弱与十神如何落到工作方式、投入节奏或关系侧重，讲到与问题相关的粒度为止，不写成正反全包的画像。回答够用就停，不规定统一字数、段落数或固定特点条数；当前材料只支持一件事，就把这一件事讲清楚。表达方式按事实选择：因果仅在规则或你的解释链明确支持时使用，位置并列不是因果；只有返回了对应时段的事实才谈趋势，没有应期依据就说明不能判断；不同体系可以比较支持、张力与不同侧面，各自机制保持在本体系内，不写“共同表明”“相互印证”式的伪综合，不投票、不平均。明确但不装确定：可写“重点是”“主要张力在于”，不每句“可能”；不把未来事件写成已知事实。

### 示范片段：解释一个有依据的重点（v3 排版）

示范前提（给宿主看，不进入正文）：仓库合成输入，`--topic character`；材料为当前 answerPlan 选中的已准入事实——紫微命宫天同坐守、亮度入庙，天同化忌在命宫，上升天蝎，太阳水瓶，月亮处女，五行俱全；规则版本 `ziwei-rules@0.1.0` 等；按 roadmap v3.4 该盘为 civil/UTC 计算，`requiredWarningCodes` 为空，正文没有也不需要任何时间精度尾注。草稿为 `reading-draft/v3`，经当前 CLI 密封并绑定送检通过，完整计划、命令与验证结果存本地证据（four-system-topic-v34-20261101）。以下才是可表达的文字（含标题与段落的原样）：

> ## 底色：温和的壳，锐利的针
>
> 这张盘的性格底色有个明显反差：紫微命宫天同坐守且亮度入庙，外在温和、随和、知足，追求生活品质；但上升在天蝎，第一印象又带点距离感和洞察力——熟了随和，不熟时偏冷静观察。太阳在水瓶进一步强化独立性：想法上不走寻常路，更在意一件事本身有没有意思、有没有公共价值。
>
> ## 内在的功课
>
> 天同在命宫同时化忌：这颗温和之星代表的安逸感，恰恰是这张盘需要面对的功课——容易在「想舒服」与「该行动」之间来回拉扯。月亮在处女让情绪需要秩序，计划被打乱时最容易烦躁。整体五行俱全，这本身不定吉凶，轻重仍要看整体喜忌的配合；这张盘的结构重心在上述几组星曜上。

它示范的写法：开头即最有价值的反差主线，短标题概括本组内容；术语（化忌、上升、月亮处女）与它在本人身上的具体表现相邻；宿主解释（“功课”“来回拉扯”）贴着事实展开、不冒充规则结论；五行吉凶的限制贴着五行那一句说清，不另起免责尾段；civil 路径没有被误加“真太阳时”提示——精度限制只在真实应用并影响所选事实时出现。示例只演示方法，实际选材依当前计划。

## 具体化与辨析

可以用一个对照、比喻或小场景帮助理解，但它必须在已获准含义之内：场景是说明，不是认定经历；没有用户自述时用“例如”“如果”“常见表现可能是”等条件表达，加“可能”不能使无依据判断合法。对照和场景只展开到获准含义的粒度——规则给了“执行”与“变动”两种侧重，就讲这两种侧重，不落到“没有改进需要时仍想变”“不喜欢长期稳定”这类原材料没有的选择偏好或行为习惯。不编造用户或伴侣的经历与隐藏动机，不用贬义标签、奉承或恐吓制造“很准”的感觉，不写“理性又感性、稳重又冲动”这类正反全包、无法区分的画像。有用的辨析要说明差别在哪里、各自在什么场景显现，先确认事实确有可比较的依据。

### 示范片段：用辨析分清两个侧面

示范前提：同一合成输入，`--topic wealth`；材料为财星正财、财帛宫天钺陀罗与金星落第四宫的已选事实（含宿主第三层解释）；草稿为 `reading-draft/v3`，经密封与绑定送检通过（证据目录同上）。用户问“这是不是说我存不下钱”。以下为用户正文：

> 「存不下钱」要拆成两面看：这张盘的进财一侧是正财——收入依赖稳定渠道、可预期，本身不是存不下钱的结构；财帛宫的陀罗提示的是周转慢（回款慢、结算周期长），拖的是时间，不等于必然漏钱。结余取决于收支两边的配合，传统结构对此没有结论，你的实际收支也不是盘面能替你回答的。支出一侧金星在双鱼第四宫，花钱偏向家人、居所与生活舒适度——若总觉得结余不理想，先核对这一侧的大额去向，比怀疑进财能力更对症。

它示范的写法：把一句复合结论拆成进财与支出两个侧面，说明各自指什么；诚实指出规则没有覆盖的部分（结余），不用盘面冒充现实答案；第三层解释（金星与支出取向）贴着事实、不冒充规则结论；无需时间精度尾注时不写。短辨析不必加标题，一两段即可。

## 同对象追问与纠正

追问只展开被问到的那一点：补机制、给一个区分或例子、必要时补会改变判断的条件。不重复整份回答，不重新定义已解释过的术语，不顺带补五行、其他体系或全部四化，也不把材料不足伪装成还有更深结论待补。比喻只对应概念：例如用“老房翻新”说明“落实方案”与“改变旧做法”这两种侧重的差别，但不再往下安排这个人如何花钱、先拆后建、讨厌审批或会怎样对待别人——那是习惯与偏好，星性没有给。用户修订对象、时间或设置时，按现有链路重新取计划、重新密封送检，不复用旧草稿。

用户说“不符合”时：先尊重对方的观察，不拿标签覆盖它。先前确实说错、说过头或漏了条件——指出具体哪一句，撤回或收窄（例如承认某个例子只用于说明概念，不是描述对方的做事方式），再据当前材料重写；现实情况未知——承认传统解释不能替代现实观察，不编造隐藏动机，也不用“你其实是这样只是没察觉”覆盖对方。解释完就停：不为维护结论自动补“还要看三方四正”“再核一次时间”等补救路线，除非输入问题与当前判断直接相关；承认不符之后不重讲全盘、所有限制和无关体系。不默认所有质疑都正确，也不维护每个判断必然成立；没有对应预测材料时直接撤回预测，禁止用“应在别处、应期延后、你已经化解”挽救。

### 示范片段：围绕同一点回答追问

示范前提：同上婚姻计划（roadmap v3.4 同对象追问）；首次回答已解释过金星双鱼与月亮处女的两个节奏，用户接着问“金星刑火星具体是什么意思”。草稿为 `reading-draft/v3`，针对同一计划重新密封并绑定送检通过（证据目录同上）。以下为用户正文：

> 单说金星刑火星这一组：它具体说的是「在意」与「起急」同时出现——金星在双鱼把感受放得很大，火星在双子让反应快而碎，一句话没接住就容易当场顶回去，事后又自己消化。多数摩擦发生在节奏被打乱、或感觉被忽视的时候，而不是原则性分歧。这组相位描述的是能量互动倾向，提示摩擦容易出现的时机，不是关系走向的断言。

它示范的写法：只解释被问的那一组相位，用“单说……这一组”衔接而不重新上课；摩擦只描述为模式与时机（第三层解释贴着相位事实），不认定用户当下正在吵架或必然经历某种场景；相位的限制随判断句就地一句，不重讲全盘、不补无关体系。追问沿用同一计划重新密封送检，不沿用旧草稿。

## 信息不足与不可答

以当前 `answerPlan.answerability`、选中事实和相关 warning 为准，不自行重新判定能力。未知时间没有获准的稳定材料时，不承诺“三柱已能确定大部分性格”，也不用午时占位生成画像；用户已说无法补时间，不再反复索取。未实现、内部失败、来源未准入和资料不足是不同原因，如实区分，不统称“资料不足”。时运不可答时直接说明，不拿本命背景或通用职场建议顶替应期答案，也不给具体月份。

## 术语要自然落地

专业名词不是每段的必选项。确有必要时再用，并在同一句或紧接着的句子里解释；已解释过的词不反复定义，不为显得专业而增加术语。

不要写：

> 七杀说明你适合竞争激烈的岗位。

可以写：

> 命盘里有「七杀」，传统上用它谈权威、压力、竞争。这只是事业与责任主题的文化参考，不是职业预言，也不能据此判断你适合什么工作。

这个例子只适用于 answerPlan 已提供该十神及其短释的情况，不是通用开场白。事业现实做法另据用户自述，不能从这条文化参考推出。没有预写短释时，用你自己的传统解释贴着该事实说明其在本题中的含义（第三层），不冒充规则结论；单人盘不替对方下判断的写法见 `examples-love.md` 的单人盘示例。

## 事业正文（ADR 0021，2026-11-01 修订 / roadmap v3.4）

事业默认正文围绕问题组织四体系事业材料：工作方式、动力、专业表达、协作、资源、责任。用户自述现实优先，可执行做法只来自用户自述；命盘侧照常解释官禄宫、MC、日主强弱与十神布局——四干没有官杀不得把整题判成没有材料，正官与七杀同现可分别陈述各自冻结短释，不选胜者。格局、喜用、五行行业与由命盘推出的职业适配鉴定仍然禁止；职业领域只作传统象义探索方向并说明需结合现实细化。只有出生信息时先给命盘分析及其条件，最多问一个关键现实问题，不给行动建议。详见 `examples-career.md`。

## 告警和边界的自然转写

只有当限制会改变当前问题的判断时才提及它。不要展示 warning 名称、错误代码、provider、规则版本、事实编号或来源路径。

| 内部情况               | 默认写法                                                                                         |
| ---------------------- | ------------------------------------------------------------------------------------------------ |
| 出生时间未知或误差较大 | 出生时间若前后相差较大，上升、宫位或时柱相关的判断可能会变化；以下更侧重对这一误差不敏感的结构。 |
| 某体系无法计算         | 当前资料不足以支持这一层面的判断，因此不作延伸推断。                                             |
| 靠近分类边界           | 这个位置靠近分界，时间稍有调整时分类可能不同，不把它当成唯一依据。                               |
| 流派分歧               | 这里不同流派采用的口径并不完全一致，因此只保留它们共同支持的部分。                               |

不受当前问题影响的内部 warning 不显示。禁止固定免责声明页脚；传统文化、非科学预测和重大决定的边界由产品入口说明。涉及健康、法律、投资、生命安全或重大关系决定时，只在对应段落中给出最小必要的自然提示。验证器要求的 caveat 与 warning 也照此转写：各挂在它所限定的判断旁边，一句说清，不堆成尾段。

## 关系与合盘

单人盘不代表两人的相互吸引、对方的想法或现有关系。只有单人结构记录时，不把它改写成合盘结论，也不把“夫妻宫”直接写成真实配偶的体貌或性格。可以解释单人结构对自己这侧的关系模式意味着什么（规则含义或第三层解释均可），但涉及“对方怎么想、是否承诺、两人合不合”时，须有实际配对结果（synastry）或用户自述的互动，叙述层的比较也不需要先建跨体系综合记录、各体系机制保持在本体系内；不得写“注定在一起”“必分手”“必然结婚”“命定伴侣”，也不得用同义表达替代。若需要说明边界，融入相关段落，例如：

> 这些结构更适合帮助你们识别靠近与卡住的方式；关系是否走得长远，仍取决于沟通、边界和双方当下的选择。

## 内部来源记录（默认不展示）

每个段落都应保留追踪信息，供测试、审计和用户主动追问时使用：段落标识、事实引用（`InterpretationFact.evidence[].ref`）、规则引用（如 `bazi-rule/...` 等版本化规则）、当前结果中的 ruleset id 与版本、reason 的受控摘要、相关 caveat 与 warning、以及本段允许写的结论。以上字段说明在本页自足可用；完整类型定义位于仓库开发文档 `docs/NARRATIVE_OUTPUT_V1.md` 的 `NarrativeTrace`，仅供开发者参考，不是安装后运行的必读依赖。

来源优先级固定为：计算出的 `ChartBundle` 事实 → 版本化 ruleset → ADR / 来源矩阵 → provider/provenance。宿主模型只能组织这些材料，不能新增盘面事实、规则或事件承诺。

## 交付前检查

普通问题一律走绑定交付链路（当前 `answer-plan` → `reading-draft/v3` 草稿 → 密封 → 带当前上下文绑定送检 → 仅展示返回的 `deliverableBody`；v2 纯文本草稿仍可用，v1 拒绝），流程与命令见 `SKILL.md` 与 `answer-contract.md`。绑定送检按本轮实际引用的事实派生 caveat 必需性：未引用事实独有的限制不再强制表达，但引用了的必须带上，warning 披露义务不变。本文各示范片段的正文即按该链路产生并通过检查的原文（含排版标记原样）；改一个字、一个标题或一处加粗都要重新密封送检，不得沿用旧正文。

对草稿文本另按需运行措辞检查：

